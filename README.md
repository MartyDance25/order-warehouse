# 数仓实训台

用模拟的电商订单，在浏览器里练习 SQL、数仓分层、ETL 口径和数据血缘。所有题目都在本机的 DuckDB 里真实执行。验收比较的是查询结果，不是 SQL 文本是不是和参考答案一字不差。

适合刚接触数据治理的同学。不需要登录，也不连接真实业务库。

## 你会练什么

八笔订单从贴源层做到运营日报。其中 O1001 可以手算：

- 两条商品明细：羽毛球拍 300 元，羽毛球鞋 100 元
- 用户一次支付 400 元。支付表里写成 40000 分
- 两天后，球鞋退款成功，退回 100 元

另外还有已下单未支付、支付失败、跨天退款、退款仍在申请中的订单，用来检查 SQL 会不会把不该算的金额算进去。

练习顺序：

1. ODS 贴源层：订单主表、订单商品明细、支付、退款。点表名可以看「一行代表什么」、字段和样例。
2. DIM 维度层：用 SKU 编码关联商品维表，补上商品名称和品类。
3. DWD 明细层：自己写 JOIN，生成订单商品明细、支付明细、退款明细。支付和退款要处理金额单位和状态编码。
4. 排错：把整单支付直接 JOIN 到两条商品明细上，再把支付金额加总，400 元会变成 800 元。先运行有问题的 SQL，再改对。
5. DWS 汇总层：用户 × 日期、SKU × 日期、店铺 × 日期。下单按下单日期，实付按支付日期，退款按退款日期。订单数按不同订单号计数。商品销售额先用商品明细金额。
6. ADS 应用层：运营日报和每日商品排行榜。
7. 运营看板读取你生成的结果表。改完 SQL 再运行，刷新看板就能看到数字变化。
8. 从日报的「实付金额」追到 ODS 源字段，并写清筛选和汇总规则。

手算总账，方便做完后核对：

| 日期 | 下单商品金额 | 实付 | 退款 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 03-01 | 1080 | 1000 | 0 | 实付是 O1001 的 400 加 O1006 的 600，不加未成功的 80 |
| 03-02 | 490 | 490 | 0 | |
| 03-03 | 150 | 150 | 100 | 100 元是 O1001 的球鞋，按退款日而不是下单日 |
| 03-04 | 120 | 120 | 40 | 40 元是 O1004 的水杯 |
| 03-05 | 100 | 0 | 0 | O1005 已下单，但支付失败 |

五日合计：下单商品金额 1940 元，实付 1760 元，退款 140 元。

## 页面怎么用

左边是练习步骤和表目录。点表名查看字段和数据。

中间是题目、目标表结构、统计口径和 SQL 编辑区。血缘题是填空，不是写 SQL。

下方是运行结果：列名、样例行、行数。失败时同时给出数据库原始报错和一句中文解释。

五个按钮：

- 运行 SQL
- 提交检查
- 查看提示。提示分步出现
- 查看参考答案。默认折叠
- 重置练习

排错题另外有「运行有问题的 SQL」。排行榜要求按日期和名次排序，其他题目行顺序不同也可以通过。

通过之后，结果表会出现在左侧「我生成的表」，后续题目直接使用这些表。侧边栏的「重置模拟数据」会清空本会话的 SQL 和结果表，并重新装入八笔订单。

## Windows PowerShell

在项目目录打开 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run.ps1
```

不想用脚本的话，可以逐条执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m streamlit run app.py --server.port 8765 --server.address localhost
```

如果 `python` 不可用，把上面的 `python` 换成 `py -3`。

浏览器打开 http://localhost:8765 。启动后就是第一道题，样例数据已经装好。

## macOS 或 Linux

```bash
chmod +x run.sh
./run.sh
```

或者：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m streamlit run app.py --server.port 8765 --server.address localhost
```

## 依赖

- Python 3.11 或 3.12
- DuckDB
- Streamlit
- pandas

版本写在 `requirements.txt`。本项目在 Python 3.12、DuckDB 2.0、Streamlit 1.40 以上验证过。

## 运行测试

```bash
python -m pytest
```

测试会用参考答案跑完整条链路，并检查错误 SQL 的反馈、排行榜顺序、看板是否读取当前结果表，以及血缘是否和参考 SQL 一致。
